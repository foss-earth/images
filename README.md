@foss-earth/images provides pure common image contracts, JPEG/PNG header checks, exact byte arithmetic, shared reservations and session queues, retained image sources, and revision-keyed persistent media storage. The host constructs one `createImageSessionBroker` and supplies it to every representation. It tracks aggregate encoded, decoded, source GPU and outstanding upload bytes; replacement overlap is a subset of the source GPU limit. No broker creates a renderer or requests frames.

The root is pure. `./browser` contains the IndexedDB adapter and common file service; `createMediaStore` receives its open port explicitly. `./node` contains the existing JPEG/PNG codecs, source orientation/colour normalization and linear-light helpers. Pure source sampling, file enumeration, validation and estimates are contributed by representation owners through `RepresentationHooks`. Spatial preparation and the representation catalogue remain with their owners.

Its predecessor's artifact receipt does not qualify these changes. The primary-generated shared CI caller/scaffold is preserved at `9e046dd482e0229dc7c7b2d71b079d5905664656`; installed owner conformance, public caller availability, coordinator verification of remote admission, lineage for newly selected source paths and current consumer adoption remain pending. Existing foss-earth/scenes remains the compatibility surface until the viewer/scene packages migrate together. No supported Node/browser range is claimed from the unchecked source draft.

Limits are supplied in real bytes/counts by the host settings registry. Unknown projections are handled by scenes/360; this package adds no projection support. JPEG/PNG are the only existing codecs. Synthetic cardinal-grid fixture bytes were generated by the original Earth example tool; source hashes are recorded in PROVENANCE.json. No campus photographs are included.

Whole-image loads return `settleReplacement()`. The host calls it after the atomic visibility swap and disposal of the outgoing source; readiness alone never releases the replacement-overlap charge. Representation loaders retain their dedicated scope until `dispose()`.

Create a session cache with `createImageSourceCache({broker, keptGpuBytes, gpuBytes, retainable?})`. `acquire(key,{signal?,priority?,overlap?,estimatedGpuBytes?,load})` shares one asynchronous factory and scope. The factory receives `(scope,{priority,overlap})` and returns a resource with idempotent `dispose()` and `settleReplacement()`. The cache measures its GPU bytes through the supplied accessor and keeps zero-reference sources by LRU within the host's kept budget. A host can mark progressive resources ineligible for retention. `evictUnused(bytes,overlap?)` makes room before a known allocation without discarding held sources. On settings changes, update the broker and call `setKeptGpuBytes`; idle sources yield to both the kept limit and a lowered total GPU limit. Broker invalidation cancels loads and disposes all cached resources.

Each pending consumer has independent cancellation; the final pending consumer cancels an unfinished factory. A late resource is disposed. A successful acquire returns `{resource,release(),settleReplacement()}`: detach from the acquire signal and explicitly release the hold. Settlement remains valid after release while the source is cached, allowing an outgoing preview borrowed by immersion to end later. Eviction already releases its overlap charge. The first factory's priority governs its queued work; later consumers share that load. `imageSourceKey` supplies the identity/revision/representation prefix. Hosts append resolved file URLs and allocation-policy variants such as atlas layout; broker generation invalidation is automatic.

`Reservation.retain()` keeps a charge after its owner releases it, until every idempotent returned hold ends. Active readers, nonabortable decoders and pending cache writes use this lifetime. Foreign decode inputs without a retain port receive a separate encoded charge until decode completes. GPU upload/staging adapters must reserve directly through the supplied `broker.pools` and release only on completion or context loss, so scope cancellation cannot free submitted work early. `ResourcePools.subscribeAvailable` coalesces releases, shrinking allocations, overlap settlement and increased limits in a microtask. Nonthrowing listeners wake the existing host frame; unsubscribe on disposal. `ResourceCapacityError.pool` distinguishes admission from invalid media; `ImageDecodeFailure` distinguishes an actual decoder rejection.

Common `decodeImageFile` returns `HeldDecodedImage` with `retain(): () => void`.
Acquire that native-input hold before an operation such as `createImageBitmap`
cropping that may continue reading the bitmap after cancellation. `close()` is
an idempotent close request: scope/session invalidation may request it, but the
actual bitmap and its existing decoded reservation stay live until every input
hold finishes. End the hold only after native completion and any late-output
cleanup. No duplicate allocation charge is added. The final release attempts
bitmap close before releasing its charge, even when the bitmap disposer throws;
repeated release/close remains inert. A closing resource rejects new holds.

The interface keeps `retain` optional for legacy supplied decoders. Such a
decoder does not establish native-input lifetime safety. Preview sheets use
original-face fallback when it is absent; another consumer must likewise choose
a compatible fallback or require the new contract. A crop promise alone does
not prove that source pixels were captured. Prepared causal fixtures cover
broker invalidation/disposal with active input holds; no qualification is
claimed until the new common artifact and its consumers are checked together.

`createImageFileService` injects broker, limits, priority, fetch, decode and optional saved files. `obtain(file,declaredBytes,scope,onChunk?,priority?)` and `decode(body,file,scope,priority?)` accept a source priority, otherwise using the host default. Cached reads consume exact admitted bytes and use a serial storage queue, independent of network request concurrency. Valid bytes survive a decode-capacity refusal. Invalid headers or an actual decoder failure forget that file. Cache persistence retains the original encoded input and charges its separate native byte snapshot until `settled()`.

The factory now returns `HeaderInferredImageFileService`. Its optional extension
on the old structural `ImageFileService` is
`obtainInferred({url,width,height,mimeType?},declaredBytes,scope,onChunk?,priority?)`.
It uses the same bounded saved-file read, network queue, transfer and persistence
path as strict `obtain`, returning `{file,header,body}`. The returned `file` has a
MIME resolved from the actual JPEG/PNG signature; both reviewed dimensions stay
required. An absent or generic served content type permits byte inference; a
contradictory served image MIME, a contradictory supplied MIME, wrong dimensions
or nonidentity EXIF orientation rejects before native decode. URL suffixes never
select a format. `declaredBytes=0` explicitly means an unknown encoded size; the
existing response cap, growing stream admission and assembly overlap still apply.
No second transport/cache or full encoded-body copy is introduced. Strict
`obtain` retains its required MIME and existing checks. `checkImageHeader` exposes
those pure checks for an already parsed header; PNG TIFF orientation now reads
bounded original offsets without allocating an EXIF-chunk copy.

`ImageHttpStatusError` reports `url`, `status` and an optional cleanup `cause`.
Common transfer treats HTTP 204 as no image and reports other unsuccessful HTTP
statuses before reading their bodies. It awaits response-body cancellation,
including a late injected cancellation, before ending its active transfer charge.
Scope cancellation takes precedence over a stale status. Engine decides that
404/204 mean a missing map tile; images does not classify sources, transparent
pixels, retries or provider policy. A body-cancellation failure remains attached
to the typed status. Common native decode also rejects and closes a bitmap whose
returned dimensions contradict its header-sized reservation.

Pure root exports `ImageDimensionMismatch` and
`imageDimensionMismatch(error): ImageDimensionMismatch | null`. The typed
observation has frozen `actual:{width,height}`, `expected:{width,height}` and
`observation:'header'|'decoded'`; it does not label a tile missing. The classifier
follows actual `Error.cause` and `AggregateError.errors` with cycle protection,
never a diagnostic string. Header observations require readable positive sizes,
matching signature/declared/served image MIME and identity orientation.
`imageHeaderError` exposes the typed variant of the unchanged string checks.
MIME, orientation, unreadable/corrupt bytes, HTTP and arbitrary native decode
failures do not acquire dimension classification. A returned native bitmap with
wrong dimensions is closed and rejected as `ImageDecodeFailure` with a typed
dimension cause; a throwing close is aggregated inside that decode failure.
This preserves cached-file forgetting on actual native decode failures. Cached
header mismatches retain the existing forget/refetch fallback, so a typed final
header error describes the fetched bytes. Engine alone applies its retained
dimension/missing policy. These source assertions are prepared and unrun.

`readbackDecodedImage({broker,scope,image,priority,label,createSurface})` borrows
an actual `HeldDecodedImage` and uses the existing decode queue. It requires the
native input hold; a legacy decoder without it rejects before allocation. Before
calling `createSurface(width,height)`, the adapter admits a `4×width×height`
decoded canvas and a separate exact RGBA output of the same size. The existing
bitmap's `4×width×height` charge is retained, giving a 12-byte-per-pixel peak for
these three allocations: 786432 bytes for 256×256, or 3145728 for 512×512. These
are allocation costs, not new limits or substituted atlas/user budgets.

A supplied `RgbaReadbackSurface` implements `read(bitmap)` returning one fresh,
exact-size `Uint8ClampedArray` or a promise, and idempotent `dispose()`. It must
clean up its own partial construction if its factory throws. If backing storage
has not retired, its optional `retired` promise must resolve only after it has.
A throwing disposal without retirement proof keeps the canvas allocation charged.
`createCanvasRgbaSurface` attempts both dimension resets and proves retirement
when either dimension is observed as zero. If both resets fail, a later explicit
`dispose()` can retry; no timer or cancellation shortcut frees its charge. Factory
failure preserves `retired` and `retryCleanup()` in `RgbaSurfaceCreationError`.
A plain factory error must leave no allocation behind. A wider backing buffer
or aliased output contradicts the supplied-port contract and is rejected. The
adapter does not race nonabortable native readback against cancellation: bitmap,
canvas and output holds survive scope/broker invalidation or disposal until native
completion. It then attempts every surface/input/output cleanup and aggregates
failures. Stale unpublished output drops and releases before ending the input
hold. Surface or final input-cleanup observers ending the operation prevent
publication. A native promise that never settles deliberately retains its input
and prospective allocations; no completion or early release is invented.

Successful readback returns `HeldRgbaImage {width,height,data,retain(),close()}`.
The native read has settled; a deferred surface retirement retains its separate
canvas grant until its proof resolves. Optional `onCleanupFailure` reports late
retirement cleanup errors without an unhandled rejection. The bitmap stays borrowed: its owner closes it
when finished. The caller closes the returned pixels after preparing pages or
retains them before further nonabortable native use. Scope invalidation requests
pixel closure; retained users keep the existing RGBA charge and data until their
last release. A closing result rejects new holds. Already borrowed raw array
references must no longer be used after final close; this lifecycle does not
claim synchronous garbage collection.

`createCanvasRgbaSurface({width,height,createCanvas})` preserves the original
`drawImage(bitmap,0,0)` / `getImageData(0,0,width,height)` path and
`willReadFrequently:true`, returning `ImageData.data` directly. Supply a fresh
canvas from the host Document or OffscreenCanvas realm; importing the browser
entry reads neither. Use this factory inside the bounded adapter. It creates no

Bounded storage uses optional `SavedFiles.getBounded(url,{maxBytes,admit})` / `MediaStoreBackend.readBounded(requests)`. Admission must precede any body clone, using the exact immutable length or a trusted transaction-consistent upper bound. An unknown custom cache is an explicit miss; the common file service never calls its unbounded `get`. The old `get`/`read` APIs remain unbounded compatibility surfaces and require caller-owned admission. New IndexedDB writes use Blob rows in `files-v2`, database version 2, inside the existing `foss-earth-scene-media-v1` database. Blob size is admitted before `arrayBuffer()`; metadata and the old row are read in one transaction. Active batch materializations all finish before failure releases their holds.

Version 1 ArrayBuffer rows are retained without migration or duplicate writes. A legacy row is read only when its aggregate group byte bound fits both the response and encoded limits; otherwise the loader falls back to the network while preserving the row. Large legacy groups can therefore miss even for a small individual file until they are evicted normally. Safely observed legacy lengths allow exact corrupt-file removal without a second body clone. Removing an unobserved old row preserves conservative group accounting until whole-group eviction. Rolling back to a version 1 opener cannot downgrade the database; that old adapter falls back to network on VersionError. Existing rows remain intact. Clearing or deleting groups occurs only through the original explicit cache actions and user limits.
