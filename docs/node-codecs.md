# Bounded Node image decoding

`@foss-earth/images/node` retains the existing PNG/JPEG decode signatures and adds an optional `ImageDecodeOptions` argument plus `inspectImageDecode`. A caller can limit encoded bytes, decoded pixels, codec memory reservations, cumulative metadata bytes and parsed chunks, and supply an AbortSignal. All limits are finite positive safe integers. The inspection result includes output RGBA bytes and the complete codec-owned working reservation, including that output. Retained caller images must be charged separately before admitting another decoder reservation.

PNG IDAT inflation cannot exceed the exact declared filtered rows. ICC and compressed XMP inflation use the remaining cumulative metadata limit. Channel/row/output buffers, encoded/IDAT copies, metadata and native output headroom are charged before inflation. Invalid/truncated rows and filters fail. JPEG gets the caller's remaining tracked allocation budget and pixel ceiling through jpeg-js, with separate conservative reservations for encoded copies, comments and metadata. This accounting bounds known codec-owned buffers and estimates ancillary/native workspace; it is not a measurement or hard bound of total process RSS, V8 objects, or garbage collection. Freed objects may remain in process memory until GC.

Cancellation is checked before inspection, between bounded PNG chunks/rows and before/after synchronous native inflate/JPEG operations. A signal cannot interrupt an operation already running on the same JavaScript thread. Hosts requiring a wall-clock interruption must isolate the job in an owned worker/process and terminate that job.

Defaults preserve the prior JPEG 400-million-pixel and 2-GiB ceilings while adding finite input/metadata/chunk limits. Production callers should use smaller budgets. `ImageDecodeLimitError.code` identifies the admission budget; malformed codec input still reports its codec error. Browser decoding, image caches, providers and renderer authority are unchanged.
